# Отчёт по Уроку 2: Линейная и логистическая регрессия

## 1. Цель работы
Реализовать линейную и логистическую регрессию на PyTorch, изучить модификации моделей (регуляризация, early stopping, многоклассовая классификация), работу с кастомными датасетами и влияние гиперпараметров на обучение.

## 2. Выполненные задачи

### 2.1 Модификация моделей (`homework_model_modification.py`)
- **Линейная регрессия**: добавлена L1 и L2 регуляризация, реализован early stopping по валидационной ошибке (patience=5).
- **Логистическая регрессия**: расширена до многоклассовой классификации через `nn.Linear(input_dim, num_classes)` и `softmax`. Рассчитаны метрики Precision, Recall, F1, ROC-AUC (macro average). Построена confusion matrix.

### 2.2 Работа с датасетами (`homework_datasets.py`)
- Создан кастомный класс `CustomCSVDataset`, наследующий `torch.utils.data.Dataset`.
- Реализована загрузка CSV, кодирование категориальных признаков (`pd.get_dummies`), нормализация через `StandardScaler`.
- Обучение на сгенерированных CSV-датасетах для классификации и регрессии с использованием `DataLoader` (batch_size=32, shuffle=True).

### 2.3 Эксперименты (`homework_experiments.py`)
- **Гиперпараметры**: сравнены оптимизаторы SGD и Adam при разных learning rate (0.001, 0.01, 0.1). Результаты визуализированы на графике зависимости MSE от эпохи.
- **Feature Engineering**: добавлены полиномиальные признаки (degree=2) через `PolynomialFeatures`. Модель с новыми признаками показала значительно меньшую ошибку на нелинейных данных по сравнению с базовой линейной моделью.

График `plots/confusion_matrix.png` демонстрирует качество многоклассовой классификации.

## 4. Выводы
- Регуляризация и early stopping эффективно борются с переобучением.
- Кастомные Dataset-классы удобны для работы с реальными CSV-файлами.
- Правильный выбор оптимизатора (Adam) и learning rate критически важен для скорости сходимости.
- Feature Engineering (полиномиальные признаки) значительно улучшает качество на нелинейных данных.

## 5. Воспроизводимость
Все эксперименты используют фиксированный `random_state=42`. Код адаптивен и работает как на CPU, так и на GPU.
